# perchance-lib

A Lua reimplementation of the text-generation engine behind
[perchance.org](https://perchance.org) random generators -- weighted
lists, nested/hierarchical lists, dynamic sub-list referencing,
inline lists and ranges, odds/weights (including dynamic odds),
`selectMany`/`selectUnique`/`selectAll`/`consumableList`, variable
assignment, ternaries and if/else, `repeat()`, and a set of
English-grammar helpers (pluralization, articles, tenses,
case transforms) matching Perchance's own text methods and `{a}`/`{s}`
smart-grammar markers.

It only covers the *text generation* half of Perchance: no input
fields, no UI widgets, no image/audio/HTML plugins, no arbitrary
embedded JavaScript. That matches generators that "don't take
inputs" -- i.e. the ones that just produce random text.

Pure Lua, zero dependencies, compatible with Lua 5.1-5.4 and LuaJIT.

## Two ways to use it

**1. Native Lua API (primary interface).** Build a generator directly
in Lua with `perchance.Generator` / `perchance.List`. List item text
uses the same `[ref]` / `{a|b|c}` mini-syntax Perchance itself uses,
so you get full expressive power without writing a line of DSL text:

```lua
local perchance = require("perchance")

local gen = perchance.new()
gen:list("adjective", { "big", "small", { value = "legendary", weight = 0.2 } })
gen:list("noun", { "sword", "shield", "amulet" })
gen:list("title", { "a [adjective] [noun]" })
gen:setRoot("title")

print(gen:run())        --> e.g. "a small amulet"
print(gen:run(12345))   --> deterministic: same seed, same output, always
```

**2. Convert an existing Perchance generator with `perchance2lua`.**
If you're starting from a generator's source on perchance.org (the
"Lists" editor panel) rather than writing one from scratch, convert
it into a standalone Lua script:

```sh
bin/perchance2lua my-generator.perchance -o my-generator.lua
lua my-generator.lua       # prints one generated result
```

The generated script is plain, readable Lua built on the native API
above (see `examples/dnd_npc.lua` for what the output looks like) --
it does not embed or depend on a DSL parser at run time, only on the
runtime engine (`require("perchance")`).

## Why two tools instead of one parser

The library's core is a *runtime engine*, not a parser for
perchance.org's indentation-based list-file format. Supporting that
full file format (multiple named lists per file, indentation-based
nesting, top-level aliases, comments) is a separate, optional layer
on top -- `tools/dslparser.lua` + `tools/codegen.lua`, wired up as the
`perchance2lua` CLI. It reads an existing generator's source once and
emits ordinary Lua source using the native API, so nothing downstream
ever needs to parse Perchance syntax again.

Both tools share the same underlying mini-expression-language
engine (`[...]`/`{...}`, weights, grammar methods) -- that part is
genuinely core to the runtime, since it's how list item *text*
cross-references other lists, with or without the DSL.

## Installation

No build step, no dependencies. Put `lua/perchance` on your
`package.path`:

```sh
LUA_PATH="/path/to/perchance-lib/lua/?.lua;/path/to/perchance-lib/lua/?/init.lua;;" lua your_script.lua
```

or add the equivalent paths in code before `require("perchance")`:

```lua
package.path = "/path/to/perchance-lib/lua/?.lua;/path/to/perchance-lib/lua/?/init.lua;" .. package.path
```

Scripts generated by `perchance2lua` expect `perchance` to be
require-able the same way -- either put `lua/perchance` next to them,
set `LUA_PATH`, or pass `--module-path` to point the generated
`require(...)` call somewhere else.

## Syntax reference

### References: `[...]`

| Syntax | Meaning |
|---|---|
| `[listName]` | Pick one item from `listName` (weighted) and substitute its (fully rendered) text. |
| `[listName.selectOne]` | Same as above, explicit. |
| `[listName.selectMany(n)]` | Array of `n` picks, with replacement. |
| `[listName.selectUnique(n)]` | Array of `n` distinct picks, without replacement. |
| `[listName.selectUnique(min, max)]` | As above, with a random count in `[min, max]`. |
| `[listName.selectAll]` | Array of every item, in order. |
| `[arrayExpr.joinItems(", ")]` | Join an array result (from the three methods above) into one string. |
| `[listName.consumableList]` | A stateful copy of the list: selecting from it removes the item, so repeated draws never repeat until the pool is exhausted. The original list is untouched. Bind it to a variable to reuse the same deck: `[cl = listName.consumableList]`. |
| `[listName.child]` | Navigate into a named nested sub-list (see Hierarchical lists below). |
| `[listName[expr]]` | *Dynamic* sub-list referencing: navigate into the child named by the string value of `expr` (e.g. `[names[g]]` where `g` holds `"female"`). |
| `[a.upperCase]`, `.lowerCase`, `.titleCase`, `.sentenceCase` | Case transforms. |
| `[a.pluralForm]`, `.singularForm` | Pluralize / singularize the trailing word. |
| `[a.pastTense]`, `.presentTense`, `.futureTense` | Best-effort tense transforms. |
| `[a.possessiveForm]`, `.negativeForm` | `cat` -> `cat's`; `is` -> `is not`. |
| `[name = expr]` | Assign `expr`'s value to variable `name`, *and* substitute it inline at this point too (matches Perchance's own behavior -- `[g = gender.selectOne]` both binds `g` and prints the chosen gender right there). Assigning a bare list reference locks in one concrete selection (so later reads of `name` all agree); the one exception is `.consumableList`, which stays a reusable handle. |
| `[name := expr]` | Silent assignment: same binding as `=` (including the bare-list and `.consumableList` rules above), but evaluates to `""` instead of `expr`'s value -- use this when you want to pick something once and reuse it later without an extra copy printed where you picked it, e.g. `[c := hairColor][c]_hair, [c]_tail`. |
| `x + y`, `-`, `*`, `/`, `%` | Arithmetic (numbers) or concatenation (`+` on non-numbers). |
| `x == y`, `!=`, `<`, `>`, `<=`, `>=` | Comparisons (numeric if both sides coerce to numbers, string otherwise). |
| `x && y`, `x \|\| y` | Short-circuiting, value-returning (JS-style, not boolean-coercing) and/or. |
| `cond ? a : b` | Ternary. |

Grammar/case methods also work directly on a bare list reference
without an explicit `.selectOne` first -- `[noun.titleCase]` is
equivalent to `[noun.selectOne.titleCase]`.

### Inline constructs: `{...}`

| Syntax | Meaning |
|---|---|
| `{a|b|c}` | Inline anonymous list; pick one option (weighted). |
| `{a|b^3|c}` | Weighted inline option (also `^1/10`, `^[dynamicExpr]`). |
| `{1-10}`, `{-5-5}` | Random integer in the inclusive range. |
| `{a-z}` | Random letter in the inclusive range. |
| `{a}` | Smart article: renders "a" or "an" depending on the word that follows it. |
| `{s}` | Smart plural suffix: pluralizes the word immediately before it (`fish{s}` -> `fishes`). |
| `if (cond) {a} else if (cond2) {b} else {c}` | Long-form conditional; each branch body is itself a template. |
| `repeat(n) {body}` | Renders `body` and concatenates it `n` times. |

### Weights (list items, `^`)

```
condiment
  pepper^2        -- twice as likely as an unweighted item
  salt
  rare-spice^1/10 -- fraction syntax
  wildcard^[x==1] -- dynamic odds: re-evaluated per selection against current variables
```

### Escapes

`\[` `\]` `\{` `\}` `\=` `\^` `\\` `\s` (literal space) `\t` (tab).
Any other `\X` is left untouched, backslash and all, rather than
having the backslash silently dropped -- so e.g. `\(object\)` passes
through as literal `\(object\)` for consumers with their own escaping
rules (Stable Diffusion prompt syntax uses `\(`/`\)` for literal
parentheses).

### Top-level definitions (DSL file format only)

```
name
  item one
  item two        -- a plain list

name = {a|b|c}     -- an alias/macro: re-rendered fresh every reference

parent
  childA           -- a nested sub-list: deeper-indented lines nest
    leaf1          -- under the preceding item, to any depth
    leaf2
  childB
    leaf3
```

One tab or two spaces per indent level. `// comment` strips to end of
line. The definition literally named `output` is the root if present;
otherwise the first definition in the file is the root.

## Feature coverage vs. real Perchance

| Category | Status |
|---|---|
| Weighted lists, fractions, dynamic odds | Full |
| Nested/hierarchical lists, dot and dynamic `[x]` navigation | Full |
| `selectOne/Many/Unique/All`, `consumableList`, `joinItems` | Full |
| Inline lists `{a\|b}`, weighted inline options, ranges `{1-10}`/`{a-z}` | Full |
| Variable assignment, ternary, operators, `&&`/`\|\|` | Full |
| `if/else`, `repeat(n)` | Full |
| `{a}`/`{s}` smart grammar, case transforms | Full, heuristic (see below) |
| Pluralize/singularize/tenses/possessive/negative | Heuristic, not dictionary-backed -- same class of limitation as Perchance's own best-effort methods. Covers common regular patterns plus ~10 common irregulars; unusual words will sometimes get it wrong. |
| Importing other generators/plugins (`{import:x}`) | Not implemented. Out of scope: this library targets self-contained generators; compose by `require`-ing another generator's Lua module and registering its lists into your own `gen.registry` instead. |
| Input fields, buttons, dropdowns (interactive generators) | Not implemented -- explicitly out of scope ("generators that don't take inputs"). |
| Image/audio/HTML plugins, arbitrary embedded JavaScript | Not implemented -- out of scope (text generation only). |
| Seeded, fully reproducible output | Not available in real Perchance (`Math.random` isn't seedable) -- an **enhancement** here: every RNG draw goes through a portable, seedable generator (`perchance.RNG`), so `gen:run(seed)` is exactly reproducible across machines and Lua versions. |
| Silent assignment (`:=`) | An **extension** beyond Perchance's own syntax, which only has the printing `=` form. Added here because "pick once, reuse several times, print nothing extra" is a common pattern (e.g. prompt-template generators) that `=` alone can't express without an awkward `&&`/`""` trick. |

## Known gotchas

- **Referencing anything that resolves to a list always draws once.**
  A bare list reference (`[name]`), a dynamic index (`[names[g]]`),
  and an assignment of a bare list reference (`[r = race]`, now
  collapsed to a concrete value -- see above) all mean "pick one and
  show it." If you reference the *same* list name twice in one
  output without capturing it in a variable first, you'll get two
  independent rolls, not the same one twice.
- **`consumableList` is the deliberate exception**: assigning
  `listName.consumableList` keeps the stateful handle rather than
  collapsing it to a draw -- but *displaying* that handle (including
  the assignment's own inline echo) still draws a card, same as an
  explicit `.selectOne`. `[cl = deck.consumableList]` already draws
  card #1 for display; a separate `[cl.selectOne]` right after draws
  card #2, not a second look at card #1.
- Comments (`//`) are stripped at the DSL-file level only, not inside
  arbitrary template strings -- a list item's text containing `//`
  (e.g. a URL) is left alone.

## Project layout

```
lua/perchance/     the runtime library (require("perchance"))
  rng.lua            seedable, portable PRNG
  grammar.lua        English heuristics: case, plural, article, tense...
  lexer.lua          tokenizer for the [...]/{...} expression language
  parser.lua         recursive-descent parser -> expression AST
  template.lua       compiles template text -> renderable fragment list
  util.lua           shared truthiness/stringify/weight helpers
  list.lua           weighted, hierarchical List class
  context.lua        per-run variable scope + RNG + list/alias registry
  eval.lua           evaluates expression ASTs against a Context
  generator.lua      Generator: the native builder API
  init.lua           public entry point, re-exports the above

tools/               the DSL file parser + Lua codegen (used by the CLI)
bin/perchance2lua    CLI: Perchance list-syntax source -> standalone Lua
examples/            a hand-authored native-API generator, plus two
                     .perchance sources with their generated .lua output
tests/               a small dependency-free test suite (run_tests.lua)
```

## Running the tests

```sh
lua tests/run_tests.lua
```

(or `lua5.1`/`lua5.3`/`lua5.4`/`luajit` -- the library and test suite
run unmodified on all of them.)
